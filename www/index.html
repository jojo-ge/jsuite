Seven apps · one edge — stable .local names, HTTPS by OrbStack

A local workbench where Claude authors and you review

jSuite is seven local apps behind one HTTPS edge — plan work, review diffs, sketch diagrams, publish explainers, get grilled about plans, draw rigged avatars, and dispatch agents on your tickets, all on localhost. Every app has a stable name, so skills and bookmarks never chase a dev-server port.

Matt Pocock's grilling interview, played by your local Claude subscription: one relentless question at a time, each with a recommended answer, until you actually share an understanding of the plan.

jAgent · Agent fleet :43007

Dispatch a fleet, watch every diff land live

Queue jTicket tickets and hand each one to a claude agent. A rail shows every run with a live diffstat, and fleet mode drains the whole queue unattended at a concurrency cap.

  • A worktree per ticket. Every dispatched agent runs in its own git worktree and tmux session, so runs never trample each other.
  • Live diffs, not scrollback. The Diff tab shows the tree changing as the agent works; the rail keeps a diffstat per run.
  • Steer the real session. The Terminal tab is the agent's actual tmux session — type into it, nudge it mid-run.
  • Accept → PR → jDiff. When the agent writes its resolution the run flips to needs-review; Accept commits, pushes, opens a PR and deep-links to jDiff.

One suite, not seven tabs

The apps share an edge, a state directory, a chart pool, a claude runner and a review loop — so work flows between them instead of getting stuck in one.

🔒

One HTTPS edge

A Caddy container proxies each .local name to its app, with OrbStack resolving the names and terminating TLS. The apps run natively on the host; only Caddy is in Docker.

🗂️

One state directory

Every app keeps its state in .data/<app>/ at the repo root — one gitignored folder to read, back up, or wipe.

📊

One chart pool

The @jsuite/charting layer serves the same charts everywhere: a chart in a jExplain article is the chart jChart opens. Edits flow both ways.

📝

A notes loop everywhere

jChart and jExplain store your annotations in .notes.json sidecars; Claude reads them and revises. Author → review → annotate → revise, on localhost.

⚡

Skills as the interface

Each app owns its Claude skills; ./jsuite setup installs them globally, and the jsuite skill carries the whole map into any session.

📌

Stable names

Always https://<app>.local — full scheme and port. No chasing dev-server ports, no broken bookmarks, no confused tooling.

Up in one command

The launcher starts all seven apps and the Caddy edge, checks their health over HTTPS, and tails their logs. ./jsuite setup handles onboarding — deps, jskills into ~/.claude/skills, OrbStack checks — in one go.

$ cd ~/code/anyway/jsuite
$ ./jsuite setup      # once: deps + jskills + OrbStack checks
$ ./jsuite start      # all seven apps + the Caddy edge
$ ./jsuite status     # pid + live HTTPS check per app
$ ./jsuite logs jdiff # tail one app (or: logs edge)
Served by the jSuite Caddy edge — static page, no process behind it. Always use https://.
