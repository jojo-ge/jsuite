A local workbench where Claude authors and you review

jSuite is jTicket: one local app that plans work, runs it in terminal claude sessions, and gives you somewhere to review every result — boards, documents, editable charts, multi-reviewer code review and a diff viewer with guided tours, all on localhost. It has a stable name, so skills and bookmarks never chase a dev-server port.

Plans land locally first, and run from the board

Projects and tickets with acceptance criteria and blocked-by edges. Claude breaks a plan down, you inspect and veto it, and then the board runs it: one ticket at a time, or hands-off through implement → merge → review → fix loops.

  • Breakdowns become boards. Claude turns a plan into tickets you can inspect, reorder and veto.
  • Local PRs. Each ticket branch squash-merges onto the project's integration branch. No push, no GitHub.
  • Hands-off runs. The jButton loops a project's AFK tickets through herdr sessions. A run plan sets out which tickets go together, who runs each, and where merges, reviews and gates sit.
  • Today, Graphs, Analytics. What needs you now, how projects lead into each other, and what each ticket took.

Documents /e

Explanations as articles, not walls of chat text

Specs, docs and explainers are block documents: prose, code, diffs, callouts, steps, timelines and a glossary, with live charts. Built for specs, walkthroughs, post-mortems and deep dives.

  • One document pool. A project's doc, a review report and an explainer are the same kind of object, read at /e/<key> and listed at /e.
  • Typed blocks. Code gets syntax highlighting, diffs get diff rendering, terms get a glossary.
  • A feedback loop. Pin a note to any block; “Copy notes for Claude” sends them all back for a revision.

Charts /charts

Claude drafts the diagram. You redraw it. Claude reads it back.

A Mermaid draft becomes an editable Excalidraw canvas. Move things, redraw freehand, pin notes to individual shapes, and Claude picks your edits up off disk.

  • Mermaid in, canvas out. After import, the canvas, not the Mermaid, is the source of truth.
  • Notes pinned to shapes. Annotate exactly the box you mean; the note travels with it.
  • One chart pool. A chart embedded in a document is the same chart the editor opens.

Reviews /reviews

Several reviewers. Only what they agree on reaches you.

A review sends two to four reviewers at a branch, each in its own herdr session, then keeps only the findings they agree on. Every review belongs to a project, and its findings are tickets on that project's board.

  • Review a GitHub PR. The Reviews board lists the codebase's open PRs. Review this PR sizes the review to the PR and writes one brief every reviewer reads.
  • Verified, not vibes. Each agreed finding is checked adversarially before it becomes a ticket.
  • Post to PR on your say-so. Pick finding tickets and post one comment review with your own gh login. It never approves and never requests changes.

Diff & tours Diff tab

Read a branch before the PR even exists

A project's Diff tab is a side-by-side diff viewer over the integration branch, a local PR, a GitHub PR or any two refs. git computes the diff locally.

  • Local-first diffs. Branch vs main works with no PR and no network round-trips.
  • Guided tours. Build tour has a claude session walk the change stop by stop. Tours are for you, never handed to reviewers.
  • Real tools. jTicket runs natively on the host, so it uses your actual git, gh and editor.

One app, not five tabs

Documents, charts, reviews and diffs live inside jTicket and share one state directory, one document pool and one claude runner, so work flows between them instead of getting stuck.

🔒

One HTTPS edge

A Caddy container proxies jticket.local to the app, with OrbStack resolving the name and terminating TLS. The app runs natively on the host; only Caddy is in Docker. Old jexplain, jreview and jchart links redirect into jTicket.

🗂️

One state directory

All state lives in .data/ at the repo root: one gitignored folder to read, back up, or wipe.

📊

One document and chart pool

A chart in a document is the chart the editor opens, and a project doc is a document in the pool. Edits flow both ways.

📝

A notes loop everywhere

Documents and charts keep your annotations in .notes.json sidecars; Claude reads them and revises. Author, review, annotate, revise, on localhost.

⚡

Skills as the interface

jTicket owns its Claude skills; ./jsuite setup installs them globally, and the jsuite skill carries the map into any session.

📌

Stable names

Always https://jticket.local, scheme included. No chasing dev-server ports, no broken bookmarks, no confused tooling.

Up in one command

The launcher starts jTicket and the Caddy edge, checks its health over HTTPS, and tails its log. ./jsuite setup handles onboarding (deps, jskills into ~/.claude/skills, OrbStack checks) in one go.

$ git clone git@github.com:jojo-ge/jsuite.git && cd jsuite
$ ./jsuite setup        # once: deps + jskills + OrbStack checks
$ ./jsuite start        # jTicket + the Caddy edge
$ ./jsuite status       # pid + live HTTPS check
$ ./jsuite logs jticket # tail the app (or: logs edge)
Served by the jSuite Caddy edge: a static page, no process behind it. Always use https://.
