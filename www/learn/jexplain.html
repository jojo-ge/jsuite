Why it exists

When you ask Claude to explain a system, a PR or a decision, the answer usually arrives as chat — unstructured, unshareable, gone when the session ends. jExplain publishes the explanation as an article: each part is a typed block, so code gets syntax highlighting, diffs get proper diff rendering, key terms get a glossary, and warnings get callouts.

Reading is only half the loop. Hover any block to pin a note — a question, a correction, a “go deeper here” — and “Copy notes for Claude” bundles all your feedback into one payload for the next revision.

The explainer loop

  1. Ask for an explainer. The j-explain skill structures the answer into typed blocks and publishes it via explain.py.
  2. Read it as an article. Open it in jExplain — real typography, rendered code and diffs, live charts.
  3. Annotate blocks. Pin notes to exactly the paragraphs or code blocks that need work.
  4. Send notes back. “Copy notes for Claude” hands your feedback to the next session; a --replace publish revises the article in place.

Skills that drive it

j-explain

Explains a concept, a PR, a system or a decision as a blog-style article in jExplain — publish, annotate, and revise with --replace. Owns the explain.py publish script and the block dialect.

Live charts, shared with jChart

Figures in a jExplain article aren't screenshots. Through the @jsuite/charting layer, the article embeds charts straight from the shared pool in .data/jchart/ — so the chart in the article is the chart jChart opens. Fix a label on the jChart canvas and the article shows the fix; pin a note on either side and Claude sees it.
