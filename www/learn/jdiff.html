jDiff — the diff reviewer

A local GitHub client that's really good at diffs: gh lists the PRs, git computes the diffs locally. Review a branch before any PR exists, draft comments offline, then open the PR and post them all in one shot.

Why it exists

Review usually can't start until a PR exists, and PR review UIs are built around the network, not the diff. jDiff inverts both: because the diff is computed by your local git, you can review any branch against main the moment the commits exist — no PR, no push, no waiting.

Comments you write are drafts, stored locally alongside ratings, tours, risks and asks. Nothing reaches GitHub until you decide it should — then the whole review posts in one batch instead of trickling out comment by comment.

The review flow

  1. Point it at the work. jdiff pr 123 for an existing PR, or jdiff branch my-feature for a branch with no PR yet.
  2. Review in the app. Walk the diff file by file; draft comments, flag risks, rate the change. Everything stays on disk.
  3. Post in one shot. When the review is done (and the PR exists), publish the drafted comments together via gh.

Drive it from the CLI

jDiff has no Claude skill — its interface is the jdiff CLI, which both you and Claude invoke directly:

jdiff pr 123              # review PR #123
jdiff branch my-feature   # review a branch vs main — no PR needed
jdiff branch my-feature --print
                          # machine-readable URL, for scripts and agents

Each invocation prepares the diff and opens (or prints) the review URL at https://jdiff.local:7443.

Host tools
Runs natively on the host (not in Docker) because it needs your real git, gh, the claude CLI, the native folder picker and open-in-VSCode.
Suite role
The review end of the loop — the branch it reviews is typically the one jimplement built from a jTicket board.
