Why it exists

Mermaid is a great language for an LLM to write and a poor medium for a human to edit. The chart editor uses each for what it's good at: Claude drafts the structure in Mermaid, jTicket converts it to an Excalidraw scene, and from then on the canvas, not the Mermaid, is the source of truth. Drag boxes, reroute arrows, redraw parts freehand; nothing gets clobbered by a regenerate.

Feedback is spatial too: instead of describing a shape in chat (“the second box from the left…”), you pin a note directly to it. Notes land in a .notes.json sidecar next to the scene, and Claude reads both to revise.

The diagram loop

  1. Ask for a diagram. The j-chart skill has Claude draft it in Mermaid and push it as a chart.
  2. Edit on the canvas. Open it at /charts/<key>: move, restyle, redraw, delete. It's a full Excalidraw editor.
  3. Annotate shapes. Pin notes to exactly the elements you mean.
  4. Claude revises. It reads the scene and your notes from .data/jchart/ and updates the diagram without discarding your edits.

Skills that drive it

j-chart

Turns a request into a diagram, opens it in the chart editor as an editable Excalidraw canvas, and gets your edits and per-shape notes back.

The shared chart pool

The @jsuite/charting package is a Nuxt layer with the Excalidraw canvas, Mermaid-to-scene conversion and a /api/charts store over .data/jchart/. Documents extend it, so a chart embedded in a document is the very same object the editor opens. Its Open editor button goes straight to /charts/<key>.
